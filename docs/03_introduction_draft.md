# Energy Detective 緒論

## A. Attention Getter｜研究動機

IEA 指出，住宅約占全球建築能源需求的七成。對住戶而言，掌握用電資訊也可能影響後續行動。Boomsma 等人的隨機對照試驗中，提供住戶即時能源資訊後，研究情境下的用電減少 2.2%。學生住宅的實地研究也觀察到，社會比較與節能能力提示可能改變用電趨勢。這些結果促使本專題追問，如何讓住戶從一段電表紀錄找出值得檢查的變化，並理解判斷所依據的資料。[1–3]

## B. Background｜應用情境與技術

Energy Detective 面向希望理解家庭用電的一般使用者。例如，住戶詢問「昨天比前天多用了多少電？我該先檢查哪個時段？」系統需要依回放日解析兩段時間，確認紀錄是否足夠，用同一單位計算差異，再把全屋與設備群的變化說清楚。現有能源 Agent 已結合自然語言與分析工具，亦有研究把文字需求轉成設備排程。本專題以 UCI 公開歷史資料驗證用電分析與檢查建議。[4, 5, 7]

## C. Problem｜研究問題

家庭用電 Agent 的回答要同時滿足三項需求。第一，數值、日期和單位可由原始紀錄或分析工具核對。第二，資料缺失或設備粒度不足時，回答的結論仍符合可觀測範圍。第三，使用者能區分歷史觀測、下一小時預測與待查成因。由此形成主要問題：**在固定資料、工具和模型的條件下，外部回答檢查能否提高數值與證據的一致性，又會帶來多少額外延遲、用量和拒答？**

## D. Existing Limitations｜既有方法與資料限制

能源 Agent 研究顯示，不同任務的正確率有差異，文字說明與工具執行結果也可能不一致。下一小時用電研究可用誤差衡量預測品質，但仍須獨立驗證 Agent 有沒有引用正確的區間、單位和結果。UCI 資料來自法國單戶，存在缺值且部分欄位為多種設備共用量測。當某組電量增加，量測可支持檢查時段與設備群，確認是哪台電器需要額外資料。[4–7]

## E. Innovation｜方法設計

Energy Detective 讓 LLM 解讀問題、選擇工具並組織答案。用電統計、MAD 候選和下一小時預測由固定工具產生。工具同時記錄資料版本、回放時點、區間、單位、品質和結果 ID，供回答與圖表共同引用。外部檢查核對日期、數字、單位、增減方向及來源，失敗時最多修正一次，仍無法核對則以已確認的觀測及限制回覆。

## F. Contributions｜預期貢獻

1. 規劃可追溯的家庭用電分析流程，涵蓋查詢、比較、異常候選、短期預測與檢查建議。
2. 透過同一模型有無外部檢查的對照，量測回答品質、失敗類型、延遲與用量。
3. 建立結合時間序列基準與 Agent 任務評分的評估設計，以單戶歷史資料驗證流程。實地節電與跨家庭使用需另蒐資料驗證。
